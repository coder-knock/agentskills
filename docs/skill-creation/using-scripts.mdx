技能可以指示智能体运行 shell 命令，并在 `scripts/` 目录中捆绑可复用脚本。本指南涵盖一次性命令、自带依赖的自包含脚本，以及如何设计面向智能体使用的脚本接口。

## 一次性命令

当现有包已经满足你的需求时，可以直接在 `SKILL.md` 指令中引用它，而无需 `scripts/` 目录。许多生态系统提供了在运行时自动解析依赖的工具。

<Tabs sync={false}>
  <Tab title="uvx">
    [uvx](https://docs.astral.sh/uv/guides/tools/) 在隔离环境中运行 Python 包，具有激进的缓存机制。它随 [uv](https://docs.astral.sh/uv/) 一起安装。

    ```bash
    uvx ruff@0.8.0 check .
    uvx black@24.10.0 .
    ```

    - 不随 Python 一起安装 — 需要单独安装。
    - 快速。缓存激进，重复运行几乎即时完成。
  </Tab>
  <Tab title="pipx">
    [pipx](https://pipx.pypa.io/) 在隔离环境中运行 Python 包。可通过 OS 包管理器安装（`apt install pipx`、`brew install pipx`）。

    ```bash
    pipx run 'black==24.10.0' .
    pipx run 'ruff==0.8.0' check .
    ```

    - 不随 Python 一起安装 — 需要单独安装。
    - `uvx` 的成熟替代方案。虽然 `uvx` 已成为标准推荐，但 `pipx` 在更广泛的 OS 包管理器可用性方面仍是一个可靠的选择。
  </Tab>
  <Tab title="npx">
    [npx](https://docs.npmjs.com/cli/commands/npx) 运行 npm 包，按需下载它们。随 Node.js 一起安装 — 无需额外安装。

    ```bash
    npx eslint@9 --fix .
    npx create-vite@6 my-app
    ```

    - 随 Node.js 一起安装 — 无需额外安装。
    - 下载包并运行，然后缓存以供将来使用。
    - 使用 `npx package@version` 固定版本以确保可复现性。
  </Tab>
  <Tab title="bunx">
    [bunx](https://bun.sh/docs/cli/bunx) 是 Bun 等效于 `npx` 的工具。它随 [Bun](https://bun.sh) 一起安装。

    ```bash
    bunx eslint@9 --fix .
    bunx create-vite@6 my-app
    ```

    - 在基于 Bun 的环境中可直接替代 `npx`。
    - 仅当用户环境使用 Bun 而非 Node.js 时适用。
  </Tab>
  <Tab title="deno run">
    [deno run](https://docs.deno.com/runtime/reference/cli/run/) 直接从 URL 或 npm 注册表运行脚本。需要 Deno 运行时。

    ```bash
    deno run npm:create-vite@6 my-app
    deno run --allow-read npm:eslint@9 -- --fix .
    ```

    - 文件系统/网络访问需要权限标志（`--allow-read` 等）。
    - 仅当用户环境中存在 Deno 时适用。
  </Tab>
</Tabs>

<Tip>
固定工具版本（例如 `ruff@0.8.0`）以确保可复现性。不固定的版本会获取最新发布版，可能在不同时间产生不同行为。
</Tip>

## 自包含脚本

对于复杂操作或自定义逻辑，在 `scripts/` 目录中放置可执行文件。智能体直接运行这些文件。

### 目录结构

```
my-skill/
├── SKILL.md
└── scripts/
    ├── check-links.sh       # Shell 脚本
    ├── generate-report.py   # Python 脚本
    └── validate-data.js     # Node.js 脚本
```

### 从 SKILL.md 引用脚本

```markdown
要验证项目中的所有链接，请运行：

```bash
bash scripts/check-links.sh https://docs.example.com
```
```

### 设计原则

- **单一职责** — 每个脚本应做好一件事。将不同操作拆分为独立脚本。
- **参数化输入** — 通过命令行参数接受输入，而非硬编码值。
- **清晰的输出** — 打印人类可读的输出以便智能体解读和传达结果。
- **错误处理** — 对失败情况使用非零退出码，使智能体能够检测错误。
- **声明依赖** — 在注释或文档中说明所需工具（例如 `# Requires: jq`）。

### 可移植性考量

<Tabs sync={false}>
  <Tab title="Shell">
    - 使用 POSIX 兼容的语法以实现最大可移植性（避免 bash 特有功能）
    - 使用 `[ ]` 而非 `[[ ]]` 进行条件测试
    - 考虑同时提供 `.sh` 和 `.ps1` 版本以支持 Windows 用户
  </Tab>
  <Tab title="Python">
    - 在 shebang 中指定 Python 版本：`#!/usr/bin/env python3`
    - 声明依赖及其版本要求
    - 使用标准库模块以减少外部依赖
  </Tab>
  <Tab title="Node.js">
    - 在 shebang 中指定 Node.js：`#!/usr/bin/env node`
    - 使用 ESM (`import/export`) 或 CJS (`require/module.exports`) 保持一致
    - 声明所需的 npm 包
  </Tab>
</Tabs>

<Warning>
脚本在用户的本地环境中运行，具有其当前权限。不要假设 root/admin 访问权限或特定工具的可用性。始终检查依赖关系是否存在并提供有用的错误消息。
</Warning>
