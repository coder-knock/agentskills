本指南介绍如何为 AI 智能体或开发工具添加 Agent Skills 支持。它涵盖了完整生命周期：发现技能、告知模型关于它们、将其内容加载到上下文中，以及随着时间推移保持内容有效性。

无论智能体的架构如何，核心集成方式都是相同的。实现细节因两个因素而异：

- **技能存放在哪里？** 本地运行的智能体可以扫描用户文件系统中的技能目录。云端托管或沙盒化的智能体需要替代的发现机制——API、远程注册表或捆绑资源。
- **模型如何访问技能内容？** 如果模型具有文件读取能力，它可以直接读取 `SKILL.md` 文件。否则，你需要提供专用工具或以编程方式将技能内容注入提示词中。

本指南会标注这些差异产生影响的环节。你不需要支持所有场景——遵循适合你智能体的路径即可。

**前置条件**：熟悉 [Agent Skills 规范](/specification)，其中定义了 `SKILL.md` 文件格式、frontmatter 字段和目录约定。

## 核心原则：渐进式披露

每个兼容技能的智能体都遵循相同的三层加载策略：

| 层级 | 加载内容 | 时机 | Token 开销 |
|------|----------|------|------------|
| 1. 目录（Catalog） | 名称 + 描述 | 会话启动时 | 每个技能约 50-100 tokens |
| 2. 指令（Instructions） | 完整 `SKILL.md` 正文 | 技能激活时 | <5000 tokens（推荐） |
| 3. 资源（Resources） | 脚本、引用、资产 | 指令引用它们时 | 视情况而定 |

模型从一开始就能看到目录，因此它知道有哪些可用技能。当它判断某个技能相关时，加载完整指令。如果这些指令引用了辅助文件，则按需单独加载。

这样既保持基础上下文较小，又让模型能够按需访问专业知识。安装了 20 个技能的智能体在启动时不会付出任何代价——只有被激活的技能才会消耗上下文空间。

## 第一步：发现技能

在会话启动时，查找所有可用技能并加载其元数据。

### 扫描位置

你扫描哪些目录取决于智能体的环境。大多数本地运行的智能体至少扫描两个范围：

- **项目级**（相对于工作目录）：特定于某个项目或仓库的技能。
- **用户级**（相对于主目录）：给定用户跨所有项目可用的技能。

其他范围也是可能的——例如，管理员部署的组织级技能，或从远程注册表获取的技能。

在每个范围内，考虑同时扫描**客户端特定目录**和 **`.agents/skills/` 目录**：

| 范围 | 路径 | 用途 |
|-------|------|---------|
| 项目 | `<project>/.<your-client>/skills/` | 你客户端的原生位置 |
| 项目 | `<project>/.agents/skills/` | 跨客户端互操作性 |
| 用户 | `~/.<your-client>/skills/` | 你客户端的原生位置 |
| 用户 | `~/.agents/skills/` | 跨客户端互操作性 |

`.agents/skills/` 路径已成为广泛采用的跨客户端技能共享约定。同时扫描它可以让用户编写一次技能并在多个兼容客户端中使用。

<Note>
某些实现还会扫描 `.claude/skills/`（包括项目级和用户级），这是出于实际原因——许多现有技能已经放置在那里。
</Note>

### 加载什么

对于每个发现的技能，读取其 frontmatter 的 `name` 和 `description` 字段。你不需要读取正文内容——这正是渐进式披露的意义所在。

将此信息组装成目录结构：

```typescript
interface SkillCatalog {
  skills: SkillMetadata[];
}

interface SkillMetadata {
  name: string;
  description: string;
  path: string; // 用于后续加载完整内容
}
```

### 将目录注入到模型上下文中

如何让模型知道可用技能取决于你的架构：

<Tabs sync={false}>
  <Tab title="文件读取模型">
    如果模型可以直接读取文件，只需告诉它去哪里查找：
    
    ```markdown
    可用技能位于以下目录：
    - .agents/skills/
    - ~/.agents/skills/
    
    每个技能是一个包含 SKILL.md 文件的文件夹。
    在开始任务之前，请扫描这些目录并列出可用的技能及其描述。
    ```
  </Tab>
  <Tab title="无文件访问">
    如果模型无法读取文件，你需要将目录信息注入到系统提示词或对话上下文中：
    
    ```markdown
    ## 可用技能
    
    ### roll-dice
    使用随机数生成器掷骰子。当被要求掷骰子（d6、d20 等）、掷骰或生成随机骰子结果时使用。
    
    ### csv-analyzer
    分析 CSV 数据文件并生成摘要、图表和报告。当被要求处理电子表格数据、分析数据集或从结构化数据文件中提取见解时使用。
    ```
  </Tab>
  <Tab title="工具使用模型">
    为模型提供一个列出可用技能的工具：
    
    ```typescript
    {
      name: "list_skills",
      description: "列出当前会话中可用的所有技能及其描述",
      parameters: {}
    }
    ```
  </Tab>
</Tabs>

## 第二步：确定何时激活技能

一旦模型知道可用技能，它就需要决定哪些与当前任务相关。这是 `description` 字段发挥作用的地方——它是主要的匹配信号。

<Warning>
不要自动加载所有技能。这违背了渐进式披露的目的，并会迅速耗尽上下文窗口。只应在模型有明确理由相信某个技能相关时才加载它。
</Warning>

### 匹配策略

有两种主要方法：

<Tabs sync={false}>
  <Tab title="模型驱动（推荐）">
    让模型自己决定。由于它拥有每个技能的名称和描述，它可以基于用户的请求进行语义匹配：
    
    ```
    用户："掷一个 d20"
    模型思考：用户想要掷骰子。"roll-dice" 技能的描述提到掷骰子。我应该激活它。
    ```
    
    这种方法最灵活，能最好地处理边缘情况和模糊请求。
  </Tab>
  <Tab title="规则驱动">
    使用关键词匹配或分类器来预过滤技能：
    
    ```typescript
    function findRelevantSkills(query: string, catalog: SkillCatalog): SkillMetadata[] {
      return catalog.skills.filter(skill => 
        matchesKeywords(query, skill.description) ||
        matchesIntent(query, skill.name)
      );
    }
    ```
    
    这种方法更可预测但不够灵活。适用于对延迟敏感的场景或当你想限制模型的自主性时。
  </Tab>
</Tabs>

无论哪种方法，结果都应该是一组相关的技能（可能为空）供模型考虑。

## 第三步：加载技能指令

当技能被确定为相关后，是时候加载其完整的 `SKILL.md` 正文了。

<Tabs sync={false}>
  <Tab title="文件读取模型">
    告诉模型读取特定文件：
    
    ```markdown
    以下技能似乎与此任务相关：
    
    ### roll-dice (位于 .agents/skills/roll-dice/SKILL.md)
    请阅读该文件并遵循其中的指令来完成用户的请求。
    ```
  </Tab>
  <Tab title="无文件访问">
    将技能正文内容注入到对话上下文中：
    
    ```markdown
    ## 已激活技能：roll-dice
    
    ---
    name: roll-dice
    description: 使用随机数生成器掷骰子...
    ---
    
    要掷一颗骰子，请使用以下命令...
    ```
  </Tab>
  <Tab title="工具使用模型">
    提供一个加载技能内容的工具：
    
    ```typescript
    {
      name: "load_skill",
      description: "加载指定技能的完整内容和指令",
      parameters: {
        type: "object",
        properties: {
          skill_name: { 
            type: "string", 
            description: "要加载的技能名称" 
          }
        },
        required: ["skill_name"]
      }
    }
    ```
  </Tab>
</Tabs>

### 处理引用的资源

技能正文可能会引用 `scripts/` 目录中的脚本或其他文件。当模型尝试使用这些资源时：

<Tabs sync={false}>
  <Tab title="文件读取模型">
    模型可以直接读取引用的脚本文件。无需特殊处理。
  </Tab>
  <Tab title="无文件访问">
    当技能引用脚本时，你可能需要在激活时将其内容一并注入：
    
    ```markdown
    ## 已激活技能：my-skill
    
    [技能正文内容...]
    
    ### 引用脚本：scripts/check.sh
    ```bash
    #!/bin/bash
    [脚本内容...]
    ```
    ```
  </Tab>
  <Tab title="工具使用模型">
    提供一个读取技能目录中文件的通用工具：
    
    ```typescript
    {
      name: "read_skill_file",
      description: "读取指定技能目录内的文件",
      parameters: {
        type: "object",
        properties: {
          skill_name: { type: "string" },
          file_path: { type: "string" }
        }
      }
    }
    ```
  </Tab>
</Tabs>

## 第四步：保持内容最新

技能会变化——作者修复错误、改进说明、添加新脚本。你的智能体应该处理这种情况。

### 缓存策略

<Tabs sync={false}>
  <Tab title="不缓存（最简单）">
    每次会话开始时重新扫描技能目录。简单但可能在大型仓库中较慢。
  </Tab>
  <Tab title="基于时间戳的缓存">
    记录上次扫描时间以及每个技能文件的修改时间。仅在文件变更后重新读取：
    
    ```typescript
    function shouldRefresh(lastScanTime: Date, filePath: Date): boolean {
      return fs.statSync(filePath).mtime > lastScanTime;
    }
    ```
  </Tab>
  <Tab title="文件监听">
    使用操作系统级文件监听（如 `fs.watch`、`chokidar`）检测变更并更新缓存。响应最快但实现复杂度最高。
  </Tab>
</Tabs>

### 处理无效技能

并非所有技能文件都是有效的。实施基本验证：

```typescript
function validateSkill(skillPath: string): ValidationResult {
  const skillFile = path.join(skillPath, 'SKILL.md');
  
  if (!fs.existsSync(skillFile)) {
    return { valid: false, error: 'Missing SKILL.md' };
  }
  
  const content = fs.readFileSync(skillFile, 'utf-8');
  const frontmatter = parseFrontmatter(content);
  
  if (!frontmatter.name || !frontmatter.description) {
    return { valid: false, error: 'Missing required fields' };
  }
  
  if (!isValidSkillName(frontmatter.name)) {
    return { valid: false, error: 'Invalid skill name format' };
  }
  
  return { valid: true };
}
```

跳过无效技能但记录警告——不要因为一个格式错误的技能而阻止整个发现过程。

## 高级主题

### 权限控制

某些操作可能需要用户批准。当技能指示执行潜在危险的操作（删除文件、运行网络请求等）时：

- 在执行前向用户显示确认提示
- 允许用户配置权限策略（始终允许、始终拒绝、每次询问）
- 考虑操作的敏感级别——读取本地文件的风险低于发送 HTTP 请求

### 技能版本控制

同一技能可能有多个版本。处理版本的方式：

- **使用 Git 分支/标签**：允许用户切换技能集合的版本
- **SemVer 版本号**：在 frontmatter 中支持可选的 `version` 字段
- **向后兼容性**：设计加载逻辑使其能优雅地处理缺失的可选字段

### 遥测和分析（可选）

跟踪技能使用情况有助于了解哪些技能有用、哪些不被使用：

```typescript
interface SkillUsageEvent {
  skill_name: string;
  activated: boolean;       // 是否被激活
  executed_successfully: boolean;
  tokens_used: number;
  duration_ms: number;
  user_query: string;       // 去除敏感信息后
}
```

确保遵守隐私最佳实践——允许用户选择退出遥测，并对查询文本进行匿名化处理。

## 实现检查清单

在声明"支持 Agent Skills"之前，请验证你的实现是否能够：

- [ ] 扫描标准技能目录（`.agents/skills/`、`~/.agents/skills/`）
- [ ] 解析 `SKILL.md` frontmatter 以提取元数据
- [ ] 构建包含名称和描述的技能目录
- [ ] 将目录信息提供给模型（通过提示词注入或工具）
- [ ] 根据用户意图确定要激活的相关技能
- [ ] 按需加载完整的技能正文内容
- [ ] 解析技能引用的脚本和其他资源
- [ ] 处理无效或格式错误的技能文件（优雅降级）
- [ ] 在技能变更时刷新缓存
- [ ] 正确处理技能名称中的 Unicode 字符
